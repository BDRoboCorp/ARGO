ProjectCenterMigration - CSV to CRM (bdgas_requestintake) mapping requirements
================================================================================

Source: BC extract.csv
Target (main table): bdgas_requestintake
Order of operations: bdgas_requestintake is created/updated first from the column mapping below, then
the chargeback rows (bdgas_budgetrequest) are created afterward using its Id.

Request Intake write payloads
-----------------------------
Existing records are retrieved by ticket for their Id only. Updates send a fresh entity containing
the CSV-mapped attributes, not the retrieved record's system columns or unrelated lookups.
Explicit nulls in mapped fields are retained so updates can clear those fields; optional fields
that are not mapped remain unchanged.
RITM Creation Date uses overriddencreatedon on create only; updates preserve the original createdon.
Records created as active and then deactivated are updated with only Id, statecode, and statuscode.
Bulk writes continue to use CreateMultiple/UpdateMultiple with custom plug-in execution bypassed;
Dataverse's built-in security and lookup validation still apply.

Chargeback function (target table: bdgas_budgetrequest)
---------------------------------------------------------
After the bdgas_requestintake record is created/updated, up to 3 bdgas_budgetrequest child rows are
created from the chargeback-related CSV columns (18, 19, 35-41, 45, 63, 64). Each row is independent -
create it only if its condition is met.

Row 1 - 1st chargeback (Development), created only if "Fee - 1st chargeback - 50% Dev" > 0:
  Date - 1st Chargeback - 50% Dev            -> bdgas_datechargeback
  Fee - 1st chargeback - 50% Dev             -> bdgas_fee
  Cost Center Dev                            -> bdgas_costcenter
  Chargeback Comments                        -> bdgas_name
  Finance POC                                -> bdgas_financepoc (lookup to systemuser, same matching
                                                 approach as other systemuser lookups above)
  bdgas_isrecurring                          = false
  bdgas_chargebacktype                       = Development
  bdgas_requestintakeid                      = the bdgas_requestintake created/updated above

Row 2 - 2nd chargeback (Development), created only if "Fee - 2nd chargeback - 50% Dev and Operations" > 0:
  Date - 2nd chargeback - 50% Dev and Operation -> bdgas_datechargeback
  Fee - 2nd chargeback - 50% Dev and Operations -> bdgas_fee
  Cost Center Dev                            -> bdgas_costcenter
  Chargeback Comments                        -> bdgas_name
  Finance POC                                -> bdgas_financepoc (lookup to systemuser, same matching
                                                 approach as other systemuser lookups above)
  bdgas_isrecurring                          = false
  bdgas_chargebacktype                       = Development
  bdgas_requestintakeid                      = the bdgas_requestintake created/updated above

Row 3 - Annual/recurring (Operations), created only if "Fee - Annual" > 0:
  Next Chargeback date                       -> bdgas_nextchargebackdate
  Fee - Annual                                -> bdgas_fee
  Cost Center Reoccuring                     -> bdgas_costcenter
  Chargeback Comments                        -> bdgas_name
  Finance POC                                -> bdgas_financepoc (lookup to systemuser, same matching
                                                 approach as other systemuser lookups above)
  bdgas_isrecurring                          = true
  bdgas_chargebacktype                       = Operations
  bdgas_requestintakeid                      = the bdgas_requestintake created/updated above
  NOTE: bdgas_datechargeback is left empty for this row (no source column maps to it).

NOT YET ACCOUNTED FOR in the 3 rows above (see open questions):
  - Chargeable (col 38): not referenced by any row.
  - BD Comment (col 19): no longer referenced by any row (bdgas_name now comes from Chargeback Comments).
